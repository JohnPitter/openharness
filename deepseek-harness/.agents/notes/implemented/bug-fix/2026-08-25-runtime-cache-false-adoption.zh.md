# Agent Note: 运行时缓存错误采纳

Status: implemented

[English](2026-08-25-runtime-cache-false-adoption.md) | 中文

## 问题

嵌入式运行时的提取缓存可能会悄悄采纳过期的运行时树。当内容印章不匹配时，`adoptRuntime` 使用 `onDiskMatchesEmbed` 作为快捷路径；该检查只覆盖 `node.exe` 大小、`dsh-runtime/lib/bin.js` 的 CRC，以及 `dsh-runtime/package.json` 是否存在。通过这些检查的目录会被写入新印章，却没有执行提取。因此，v0.1.20 到 v0.1.24 发布的运行时修复仍可能缺失于受影响机器，使上下文溢出分类和压缩修复看起来失效。取证证据包括当前印章 `c1bd763daeeb4c211b6b506d24618dc49f7a4f61` 与横跨 8 月 22 日至 24 日的混合时间库文件；`@deepseek-ai/dsh-llm-pi-ai/lib/index.js` 已过期，缺少 v0.1.24 的上下文溢出分类。

## 决策

印章不匹配时始终执行增量 `unzipRuntime`，并且只有提取成功后才写入印章。`internal/sidecar/sidecar.go:133-137` 及其位于 `:151-155` 的同级路径移除了不可靠的 `onDiskMatchesEmbed` 快捷路径。印章文件格式 epoch 会让旧逻辑生成的印章恰好一次被视为不可信，因此带有已损坏目录的机器会自愈；后续启动恢复使用廉价快捷路径。增量提取会跳过大小和 CRC 均匹配的条目，只重写确实改变的文件。

交付的运行时还会将 pi-ai 上下文溢出错误分类为 `CONTEXT_WINDOW_EXCEEDED`，并让 `/compact` 在同一事务内重试，同时将摘要器跨度预算减半。摘要器默认 `maxTokens` 为 8192；如果在 272000 token 窗口中显式设置为 128000，跨度预算可能为零，继续减半也无法恢复。

## 备选方案

**保留三字段的 `onDiskMatchesEmbed` 验证。** 不予采用：稳定的哨兵文件可以匹配，而其他运行时文件仍然过期，因此该检查无法证明提取目录与嵌入内容一致。

**每次不匹配都删除并完整提取运行时。** 不予采用：增量提取在修复实际变化条目的同时保留缓存性能。

## 影响

带有旧的、看似当前印章的现有安装会执行一次自愈提取，然后恢复快捷路径。提取失败时保留旧印章，因此下一次启动会重试，而不会认可不完整目录。压缩恢复可以随可执行文件实际提取的运行时文件交付。

## 测试

`internal/sidecar/` 中的回归测试覆盖需要提取的印章不匹配、旧格式印章自愈、提取失败后的印章写入顺序，以及匹配条目的增量跳过。运行时压缩测试覆盖上下文溢出分类和事务内跨度减半重试。
