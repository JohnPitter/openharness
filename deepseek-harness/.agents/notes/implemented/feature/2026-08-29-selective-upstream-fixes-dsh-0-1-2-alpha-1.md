# Agent Note: Selective fixes and features adopted from upstream dsh-v0.1.2-alpha.1

Status: implemented

English | [中文](2026-08-29-selective-upstream-fixes-dsh-0-1-2-alpha-1.zh.md)

## Problem

Upstream `deepseek-ai/deepseek-harness` published `dsh-v0.1.2-alpha.1`, roughly 1,079 commits ahead of the `dsh-v0.1.1-rc.2` base this fork last synced from. Two of that release's changes are architecture-scale (the `ApiProxy` package removed in favor of a `@Remote` gateway that this fork's compaction and same-session revision work is built directly on top of, and a full module split of the conversation UI that this fork's activity-summary fold and desktop sound work sit inside) and are deliberately deferred to a dedicated upgrade project rather than folded in piecemeal. The remaining changelog entries are self-contained bug fixes and small features with no architectural dependency on either deferred change, and porting them individually — verifying each against this fork's actual (diverged) file layout rather than copying blindly — captures real upstream value now without waiting on that larger migration.

## Decision

Eight upstream fixes were ported by hand, each verified to compile, typecheck, and pass its focused tests against this fork's current tree, and each adapted where this fork's file layout, package boundaries, or prior local features diverged from upstream's:

1. **System-prompt section order tie** (`packages/workflow/tool-workflow/src/index.ts`): `tool:cordis` and `tool:workflow` both declared `order: 115`; a stable sort then broke the tie by plugin-activation order, which varies across platform compositions. `tool:workflow` now declares `115.5`, preserving its established position after `tool:cordis` regardless of activation order. Direct, verbatim port — no fork divergence in this area.
2. **Composer Send/Stop reflects the draft, not just running** (`packages/client/ui-conversation/src/client/skeleton/InputBar.tsx`): while a turn is running, the primary button now stops only when the composer is empty or blocked; an actionable draft shows Send (queuing it) instead of forcing a Stop click first. Direct port; this fork's `empty`/`blocked` locals matched upstream's pre-fix shape exactly.
3. **`str_replace_editor` tolerates `null` placeholders** (`packages/fs/tool-str-replace-editor`): a command-specific field the selected command does not use (e.g. `view_range` on `create`) now accepts an explicit `null` as equivalent to omission, while required fields for the selected command still reject `null`, and `str_replace.new_str` still only treats omission (never an explicit `null`) as a deletion. Model-generated calls that serialize unused fields as `null` placeholders no longer fail validation. This fork had not yet received this fix from upstream; the port was verbatim.
4. **Blank sessions never count against the Workspace fold quota** (`packages/client/ui-workspace/src/client/WorkspaceBrowser.tsx`): a provisional New Session row rendered for free; only ordinary rows count toward the five-row collapsed limit, and collapsed-mode drag-and-drop now anchors against the previous *visible* row and rejects any drop that would refold the dragged row out of sight. Ported to this fork's actual file (`src/client/WorkspaceBrowser.tsx`; upstream's equivalent lives one directory deeper).
5. **WebSocket idle connections send a keep-alive heartbeat** (`packages/client/connection/src/{index,websocket-downlink}.ts`): a configurable `websocketHeartbeatIntervalMs` (default 30s, schemastery-validated against `MAX_TIMER_DELAY_MS`) drives one unref'd interval per server that Pings every open socket; no pong deadline, matching upstream (half-open detection stays with TCP). Upstream added this to `packages/api/gateway`'s `RemoteStreamMuxServer`, which does not exist in this fork; this fork's only WebSocket server is `WebSocketDownlinks` in `packages/client/connection`, so the heartbeat was ported there instead — the one substantive architectural adaptation in this batch. `packages/host/apiproxy` carries no WebSocket code and this fork's compaction/session-revision logic there is untouched.
6. **`ask_user_question` drafts survive a Session switch** (`packages/client/ui-user-questions`): in-progress answer selections, custom text, and page position now live in a new per-Session `createQuestionDraftStore()` instead of component `useState`, so switching away from and back to a session restores exactly where the user left off. Adapted: upstream's store imports from a separate `dsh-client-store` package this fork does not have; this fork's `draft-store.ts` imports `defineStore`/`EngineStoreHandle` from `@deepseek-ai/dsh-client-runtime/client` instead, the same engine every other Session-scoped store in this fork already uses, so no new package or tsconfig dependency was needed.
7. **Streaming code fences highlight incrementally** (`packages/client/ui-primitives/src/markdown`): a still-streaming fenced code block now tokenizes and highlights syntax as it grows (resuming shiki's `GrammarState` so completed lines never re-tokenize) instead of rendering plain text until the fence closes. This fork's pre-fix markdown files were byte-identical to upstream's, so the port applied verbatim aside from this fork's pre-existing optional Chinese-default `codeLabels` prop.
8. **Persistent Bash/PowerShell results become expandable** (`packages/client/ui-tool`): a settled persistent-shell call (identified by a description-less `command`-only argument object — the marker the persistent providers use, since standard bash/pwsh schemas require a description) now expands through the generic input/output card instead of staying permanently collapsed with its output unreachable. Adapted: this fork's toolview architecture derives presentation from `callView`/`resultView` render intents rather than upstream's raw-argument `raw-tool-call.ts` helper (absent here), and this fork's `ToolCallBlock` carries no `parentCallId`, so upstream's child-call exclusion was not ported (a description-less child bash call becoming expandable is harmless — pwsh already routes through the always-expandable generic `ToolRow`).

Nothing already built in this fork — the activity-summary fold, the Kimi/Cursor/GLM providers, the pt/es locales, the rebrand, the compaction fixes, the same-session message revision, or the task-complete sound work — was removed or replaced; every port is additive or a narrow behavioral correction inside a file this fork already owned.

## Alternatives considered

**Merge upstream `master` wholesale.** Rejected for this pass: an alpha pre-release, 6,421 files of delta, and the two architecture-scale changes above would each require a dedicated porting effort (compaction and revision onto the `@Remote` gateway; the conversation UI's activity-summary fold and desktop-complete logic onto upstream's split module layout) that a single incremental change should not bundle with unrelated bug fixes.

**Cherry-pick upstream commits directly with `git cherry-pick`.** Rejected: this fork's tree has diverged enough (rebrand, additional providers, additional locales, prior local fixes in the same files) that a raw cherry-pick would conflict on most of these commits; each fix was instead re-derived from the upstream diff and its Agent Note, then hand-applied against this fork's actual current file content.

## Consequences

This fork gains eight verified upstream fixes without the deferred architectural migrations, each independently revertible (they touch narrowly-scoped, mostly non-overlapping files) and each covered by its own focused tests carried over or adapted from upstream. The `packages/client/connection` WebSocket heartbeat is the one place this batch introduced a genuinely new mechanism rather than a straight port, because upstream's equivalent server does not exist here — future upstream syncs touching `packages/api/gateway`'s stream server will need to reconcile against this fork's `WebSocketDownlinks` location instead. The deferred `ApiProxy` removal and conversation-UI module split remain open work for a dedicated upgrade pass once upstream reaches a stable (non-alpha) `0.1.2`.

## Verification

Each fix carries its own focused unit/component coverage (added or adapted from upstream's), all green individually and re-run together across every touched package in one consolidated pass (`packages/client/connection`, `ui-conversation` desktop-complete/input-bar, `ui-primitives` markdown, `ui-tool`, `ui-user-questions`, `ui-workspace`, `fs/tool-str-replace-editor`, `workflow/tool-workflow`): 1,206 of 1,209 tests pass, with the 3 failures independently confirmed pre-existing at the already-shipped v0.1.51 baseline (via `git stash` against the root repository's committed HEAD, not this batch's changes) and left untouched, as fork breakage on code none of these eight ports touch. `tsc -b tsconfig.client.json` and `tsc -b tsconfig.host.json` both pass clean; oxlint on every touched production file reports zero errors.
