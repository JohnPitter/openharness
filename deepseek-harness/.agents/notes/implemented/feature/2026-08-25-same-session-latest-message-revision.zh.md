# Agent Note: 在同一会话中修订最新已完成用户消息

Status: implemented

[English](2026-08-25-same-session-latest-message-revision.md) | 中文

## 问题

用户需要在不创建第二个对话、也不让过时轮次继续出现在活动对话中的情况下修正最新已完成的提示词。仅替换客户端投影无法让持久重放、模型输入、搜索和 token 计量保持一致，而重试还不能让修订后的提示词执行两次。

## 决策

编辑仅限同一会话中的最新已完成用户消息。它保留会话 id，绝不创建 fork。Host 使用共享的每会话接纳与取消路径，然后追加一个持久修订 cut：该 cut 以最新已完成用户消息为锚点，并从活动投影中移除截至所捕获日志尾部的旧用户／生成的 assistant／tool／milestone／todo 尾部。替换消息也追加在同一会话中。

每个消费会话历史的活动投影都会折叠修订 cut。因此，对话表面、模型可见历史、会话搜索和 token 计量都会排除被移除的尾部并包含替换消息。每次重复编辑都以当前最新已完成用户消息及其产生的修订为锚点，因此支持连续修订。

每个操作都使用确定性的 `operationId`，由会话、锚点身份和规范化后的替换内容派生。重复接纳会返回已提交的修订，而不再次分发响应。持久化屏障先于分发：提交后、分发前发生崩溃时，修订消息可能没有响应；恢复路径是用户重新生成，而不是把操作作为重复的模型或工具工作重试。

显式 fork 保留已有的种子边界和语义。本功能只编辑活动会话，不重新解释 fork 的创建或历史。

## 考虑过的替代方案

**每次编辑都 fork 会话。** 不予采纳，因为修正是同一会话操作，而新会话会拆分身份、持久历史、搜索结果和用户可见连续性。

**只替换客户端投影或截断存储。** 不予采纳，因为这些路径会让模型重建、搜索、token 计量或崩溃恢复看到不同历史；追加式修订事件为所有消费方提供一个持久来源。

**提交修订后在每次重试时都分发。** 不予采纳，因为提交与分发之间的崩溃会让调用方重试时重复修订响应；宁可采用至多一次分发，也不自动产生重复工作。

**改变显式 fork 语义以共享修订 cut。** 不予采纳，因为 fork 具有独立的种子边界，现有调用方依赖该边界保持不变。

## 后果

修订是追加式持久历史，而不是破坏性删除日志；活动投影会隐藏被取代的区间。提交后的编辑在崩溃后可能暂时只显示修订后的用户消息而没有响应，用户可以明确重新生成。共享的接纳与取消路径会让编辑与同一会话中的其他工作串行化，确定性的操作 id 让重试具备幂等性，但不承诺自动恢复响应。
